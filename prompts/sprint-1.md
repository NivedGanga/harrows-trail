# Harrow’s Trail — Sprint 1 Prompt: Playable Vertical Slice

You are the gameplay engineer for **Harrow’s Trail**, a single-player Western story mod for Luanti running on a pinned Mineclonia release. Read the project/repository first and use the supplied **Harrow’s Trail Game Design Document** as the source of truth. Implement **Sprint 1: a playable vertical slice**, not just scaffolding.

**Outcome:** From a fresh world, a player can investigate the burned Harrow Ranch, find the first clue/map fragment, recover Samuel’s saddle, tame and saddle a Mineclonia horse, travel to a compact Red Mesa entry, meet Sheriff Ada Wells, and make one consequential playable choice that changes a persistent story flag and produces an observable response. The player can save, leave, rejoin, and continue.

**Work:** First verify the repository, Luanti/Mineclonia versions and actual item/node/API names. Pin/document the versions. Create only the mod foundation needed now; implement versioned player state and reliable save/load, the ranch slice, objective/journal feedback, the horse/saddle path using Mineclonia’s native horse behavior, Ada’s first dialogue, and one short encounter or choice. Samuel’s saddle must be guaranteed and recoverable. Keep the scope small, use simple available blocks and placeholder visuals, and lock any debug commands behind a development privilege.

**Constraints:** Do not implement a custom horse or riding system. Test native riding and persistence first and add only a minimal compatibility layer if necessary. If an engine/game limitation blocks riding in this sprint, keep the slice playable with an explicitly temporary substitute and report that the native-horse criterion remains open; do not conceal the gap. Do not build Acts 3–10, a timer, broad NPC schedules, full weather, elaborate cutscenes, or final art/audio. Do not make an inventory gate the whole activity: include exploration and an understandable story beat.

**Done means:** The mod loads cleanly in the pinned setup; the slice is playable by a normal player; the choice, objective, and progress persist across logout/rejoin; the journal makes the next action clear; no developer command is needed to finish; and a short manual test record lists setup, steps, results, known limitations, and the exact versions. Run available checks and fix errors before reporting. Summarize changed files, how to install/run the build, acceptance-test results, and any deferred decisions. Do not start Sprint 2 work.
